# 14주 실외 데모 점검표

2026-11-22, M51. 데모는 앱 기본 설정을 측정용(bench) 빌드로 설치해서 한다. 앱 기본 설정은 하네스 머리 오프셋, 가슴 고정 진행 방향, 의미 모드 조합(C: 의미 라벨·움직이는 장애물 추적, 신뢰도 무게와 발 접점은 뺌)을 포함하고, 근거리 조기 STOP은 꺼져 있다. C는 확인용 녹화의 미리 정한 규칙으로는 켜지 않는 것이었지만 데모에 쓰기로 정했다(`docs/DECISIONS.md` 2026-11-22 M51).

## 하는 방식

- S10은 사용자 모드만 돌린다. 걷는 모습은 액션캠 같은 별도 카메라로 찍는다(3차 멘토링: S10에 부하를 더하지 않음).
- 장소는 확인용 녹화를 찍은 캠퍼스 광장 보도블록을 권한다. 판정한 장면이 그곳의 장면이다.
- 보일 장면: 다가오는 사람(확인용 녹화에서 3번 중 2번은 사람이 1 m 안에 들어오기 전에 STOP), 고정물 앞까지 걸어가 멈췄다 비켜 가기, 보행상황 말(점자블록 등).
- 보이지 않을 장면: 내려가는 계단(노면 모델이 내려다본 계단을 칠하지 못함), 횡단보도 신호(교통상황 기능은 뺌), 차도.
- 알고 있는 약점: 광택 있는 검은 차처럼 주변을 비추는 물체는 깊이 영상에 실제보다 멀게 찍혀 장애물로 잡히지 않을 수 있다(T01에서 블록 위 검은 차를 3 m 안에서 놓침, 발 접점은 꺼서 라벨로도 잡지 않음). "사람 다가옴"은 발 접점을 끈 뒤 STOP 즈음에 나온다. 의미 라벨은 실외에서만 나오므로 실내에서는 라벨 없이 돈다. C로 10분 넘게 돌려 처리 시간을 잰 적은 없다. 신뢰도 무게는 뺐다(원시 깊이 신뢰도가 낮으면 지도가 비고, 돈 직후 가까운 물체를 늦게 알렸다).

## 점검표

| 언제 | 할 일 | 까닭 |
|---|---|---|
| 전날 | `.\gradlew.bat :app:installBench`로 설치한다. 기기 덮어쓰기 파일(`/sdcard/Android/data/hearspace.app/files/config.override.json`)이 없는지 확인한다(`adb shell ls`) | 디버그 빌드는 새 처리를 2배 넘게 느리게 한다. 남은 덮어쓰기는 기본 설정을 바꾼다 |
| 시작 전 | 배터리 90% 이상, 폰이 식은 상태(30 °C 안팎)에서 시작한다 | 실내에서 30분에 배터리 20%p, 10분에 약 10 °C 올랐다 |
| 시작 | 하네스를 늘 같은 위치에 차고, 정면을 보고 선 채로 사용자 모드를 켠다. 상태가 정상이 될 때까지 기다린다 | 가슴 고정은 첫 자세에서 몸 정면을 정한다. 하네스가 비뚤면 그 각만큼 통로가 치우친다 |
| 서 있을 때 | 화면 아래쪽에 바닥이 보이는 자세를 유지한다 | 바닥을 모르면 확인 불가가 된다 |
| 중간 | 한 번에 10분 안. 폰이 뜨거우면 그늘에서 쉰다 | 실외는 실내보다 뜨겁다 |
| 깊이 멈춤 | 추적은 정상인데 확인 불가가 몇 초 넘게 이어지면 앱을 다시 시작하고 시각을 적는다 | ARCore가 같은 깊이 영상을 되풀이하는 현상(실내 30분 중 약 30%). 앱에서 고치지 않기로 했다 |
| 끝난 뒤 | `adb shell ls -t /sdcard/Android/data/hearspace.app/files/runs`로 데모 실행 폴더를 찾아 `adb pull`로 가져온다(device.csv, stage_timing.csv, input_timing.csv) | 실외 발열·처리 시간·깊이 멈춤 횟수 기록. C의 처리 시간은 이 기록으로 처음 본다 |

## 중계 (M68, 리허설 전 초안)

데모는 실외 생중계다. S10(bench 빌드)이 안내 출력·화면·말 사건을 집 데스크톱의 중계 서버로 올리고, 청중은 폰 브라우저로 보행자와 같은 소리·화면을 받고 아래 채팅창으로 이야기한다(milepost `demo-relay`, 명세 §16). S10 안내는 중계가 끊겨도 그대로다.

**처음 한 번.** DuckDNS 이름을 만들고 이름·토큰을 git 밖 `data/relay/ddns.json`(`{"name": "...", "token": "..."}`)에 둔다. 공유기(ipTIME)에서 TCP 80·443을 데스크톱으로 넘기고 데스크톱 IP를 고정 할당한다. Caddy를 처음 켤 때 Windows 방화벽 창에서 개인 네트워크를 허용한다. S10을 동행자 폰 핫스팟에 한 번 연결해 둔다(S10에는 유심이 없다).

| 역할 | 자리 | 가진 것 | 하는 일 |
|---|---|---|---|
| 보행자 | 광장 | S10(하네스), 이어폰 | 안내만 듣고 걷는다 |
| 동행자 | 광장, 보행자 옆 | 자기 폰(핫스팟 켬, 중계 페이지, 소리 줄임) | 안전을 지킨다. 채팅으로 온 지시를 말로 전하고, 깊이 멈춤 때 앱을 다시 켠다 |
| 촬영자 | 광장 | 폰(화상회의, 마이크 끔) | 걷는 모습을 송출한다 |
| 운영자 | 교실 | 노트북 | 영상과 중계 페이지를 나란히 띄우고, 채팅으로 진행을 알린다 |
| 평가자·청중 | 교실 | 각자 폰, 이어폰 | 듣고 보며, 채팅으로 지시하거나 묻는다 |

| 언제 | 할 일 | 까닭 |
|---|---|---|
| 전날 | 앱(`:app:installBench`)과 서버를 같은 커밋에서 빌드한다. 앱 말 문장이 바뀌었으면 `tools/relay/s10.ps1 -Clips`로 말 소리 모음을 다시 만든다 | 앱과 서버의 코어가 다르면 소리가 달라진다(서버가 커밋이 다르면 경고) |
| 전날 | 집 데스크톱에서 `./gradlew :viewer:relay`와 `powershell -File tools/relay/home.ps1`을 켜고, Wi-Fi를 끈 폰으로 `https://<이름>.duckdns.org/?k=<보기 열쇠>`를 열어 본다. 절전과 Windows 업데이트 재시작을 끈다 | home.ps1이 DuckDNS를 지금 집 IP로 갱신한다. 서버가 멈추면 중계만 끊긴다 |
| 전날 | S10을 PC에 꽂고 `s10.ps1 -Url https://<이름>.duckdns.org` | 업로더는 작동 화면이 열릴 때 기기 파일을 읽는다 |
| 30분 전 | 노트북에 화상회의 창과 페이지 창을 나란히 띄우고 노트북 소리는 끈다. 페이지 창 주소창의 “QR 코드”로 QR을 띄운다. 청중에게 교실 Wi-Fi를 권한다 | 소리는 한 명 10분에 약 115 MB다 |
| 시작 | 동행자 폰 핫스팟을 켜고 S10 사용자 모드를 켠다. 동행자 폰도 페이지를 열어 탭하고 소리를 줄인다 | 페이지 화면은 소리를 켜야 움직인다 |
| 걷기 | 고정물과 사람은 걸어가며 보인다 | 서 있으면 주의 구간 소리가 없다(2026-11-23 결정) |
| 깊이 멈춤 | 최근 앱 화면에서 앱을 닫고 다시 켠다. 시각을 적고, 운영자가 채팅으로 알린다 | 작동 화면만 다시 열면 멈춤이 이어진다(M67). 청중 화면은 “중계 끊김” → “준비 중” → 안내로 돌아온다 |
| 끝난 뒤 | S10 실행 기록(위 점검표)과 서버 기록 `data/relay/runs/<시각>`을 남긴다. 서버와 Caddy를 끄고 공유기 포트 넘김을 끈다 | 집 PC를 인터넷에 열어 두지 않는다 |

S10 핫스팟이 끊기면 보행자 안내는 그대로이고, 2 s 뒤 청중 화면이 “중계 끊김”이 되며 소리가 꺼진다. 서버가 멈추면 S10에는 영향이 없으므로 영상만으로 이어 간다.
