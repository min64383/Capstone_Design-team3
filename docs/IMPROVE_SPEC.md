## 0. 한 줄 요약

녹화 세션을 오프라인으로 재생해 **주변 여러 물체의 방향·거리·높이를 소리만으로 정확히 알 수 있는 공간 음향**을 만든다. 군집·추적·음원화 방법을 바꿔 가며 비교하고, 정량 지표와 함께 **평가 GUI에서 직접 보고 들으며** 정성 평가한다.

## 1. 문서 관계

- `MVP_SPEC.md`는 M0~M10의 기록으로 고치지 않는다. 이 문서에 따로 적지 않은 것은 MVP 명세를 따른다.
- **그대로 이어받는 것:** 좌표계 규약(§5), 세션 형식(§8, `docs/FORMAT.md`), 설계 원칙(§2.2) 전부, 작업 규칙(§14), 설정 원본(`app/src/main/assets/config/default.json`).

## 2. 목표와 범위

### 2.1 "정확한 공간 음향"의 정의

사용자가 소리만 듣고 다음을 알 수 있어야 한다.

1. **어디에**: 각 물체의 방향(머리 기준 방위각)과 거리
2. **무엇이**: 높이 유형(바닥에서 올라온 것 / 머리 높이 돌출), 대략의 크기(좁은 기둥 vs 넓은 벽)
3. **몇 개**: 서로 다른 물체가 따로 들린다(합쳐지거나 한 물체가 둘로 갈라지지 않는다)
4. **위험한 것이 먼저**: 가까이 다가오는 진행 방향의 물체가 다른 소리에 묻히지 않는다

정량 목표는 §9.2(가설), 정성 목표는 §9.3 평가로 판정한다.

## 3. 설계 원칙 (MVP §2.2에 더해)

1. **오프라인이어도 인과적이다.** 재생에서도 현재 시각 이후의 프레임·자세·깊이를 쓰지 않는다. 미래를 보는 방법은 기기로 옮길 수 없으므로 채택 대상이 아니다. (MVP §2.2-1 그대로, 오프라인 예외 없음)
2. **기준선 보존.** 모든 변형은 설정으로 고르고, **기본 설정은 MVP 동작을 그대로 재현**한다. 새 방법은 기준선과 같은 세션·같은 지표로 비교해서만 기본값이 된다.
3. **실행 시간은 기록한다.** 단계별 처리 시간(PC, 깊이 프레임당 ms)을 실행 로그에 남기고 보고서에 적는다. 형식은 `stage_timing.csv`(`tCaptureNs, mapNs, clusterNs, trackNs`, 실제 시계라 실행마다 달라서 다른 로그와 파일을 나눈다), 요약은 `metrics.json`의 `stageMs`. 이 단계에서는 예산을 넘어도 탈락시키지 않지만, 기기 이식(M17) 때 근거로 쓴다.
4. **교체 가능한 단계.** 분할·군집·추적·음원 선택·음원화는 각각 한 인터페이스 뒤에 두고 설정으로 구현을 고른다(§4). 구현이 하나뿐인 단계에는 인터페이스를 만들지 않는다.
5. **안전 원칙은 실험 대상이 아니다.** 정보 만료, 무음 ≠ 안전, 시야 밖 보존, 확인 불가 알림은 어떤 변형에서도 유지한다. 특히 **STOP 대상은 다른 음원에 묻히지 않는다**(§8.3).
6. **core의 순수성 유지.** 새 알고리즘도 `core`(순수 Kotlin)에 둔다. 프로토타입은 `prototypes/`(MVP §14-10).

## 4. 파이프라인 구조

```
깊이 ─▶ [앞단] ─▶ [바닥] ─▶ [복셀 맵(시야 밖 보존)] ─▶ [분할] ─▶ [군집] ─▶ [추적] ─▶ 물체 목록
                                                                                      │
자세 ─▶ 진행 방향·머리 ──────────────────────────────────────▶ [음원 선택] ─▶ [음원화] ─▶ 바이노럴
```

- 대괄호 단계가 교체 대상이다. 바이노럴 렌더러(HRTF 합성)는 MVP 구현을 쓰고, 개선이 필요하면 같은 방식으로 교체 대상에 넣는다.
- **앞단(v0.3):** 깊이 영상 한 장을 지도에 넣기 전에 다루는 단계(가장자리 판정, 영역 분할, 평면 표시, §6.1 M13.1). 기본값은 꺼짐(MVP와 같이 깊이를 그대로 지도에 넣음). 바닥·복셀 맵도 v0.3부터 교체 대상이다(§6.1 M13.2·M13.5).
- 느린 경로(분할~추적)와 빠른 경로(음원 선택~음원화)의 분리와 최신 값 전달은 MVP와 같다.

### 4.1 데이터 계약 (초안, M11에서 확정)

```kotlin
/** 분할 결과의 복셀 꼬리표. */
enum class VoxelLabel { FLOOR, STRUCTURE, OBJECT, UNKNOWN }

/** 추적 중인 물체 하나(느린 경로 출력). 좌표는 월드(W), 단위는 이름에. */
data class TrackedObject(
    val id: Int,
    val tCaptureNs: Long,          // 마지막으로 관측에 반영한 깊이 시각
    val centerW: Vec3,
    val aabbMinW: Vec3, val aabbMaxW: Vec3,   // 회전 상자가 필요해지면 M13에서 바꾼다
    val heightClass: HeightClass,
    val label: VoxelLabel,         // OBJECT 또는 STRUCTURE
    val confirmed: Boolean,        // 확인 규칙(연속 관측)을 통과했는가
    val ageS: Float,               // 처음 관측 후 경과
    val unseenS: Float,            // 마지막 관측 후 경과(시야 밖 보존 중이면 증가)
    val velocityW: Vec3?,          // 이동 물체 추적을 켰을 때만
)

/** 음원 하나(빠른 경로 출력, 오디오 블록마다). MVP AudioCmd를 대신한다. */
data class SourceCmd(
    val objectId: Int,
    val azimuthDeg: Float, val elevationDeg: Float, val distanceM: Float,
    val band: Band, val priority: Int,       // 0이 가장 높음
    val sound: SoundKind, val gain: Float, val widthDeg: Float,
    val infoAgeMs: Float,
)
```

- 설정 키는 새 묶음으로 둔다: `perception.*`, `frontend.*`·`slowPath.*`(v0.3), `segment.*`, `cluster.*`(기존 확장), `map.*`·`floor.*`·`track.*`(기존 확장), `sonify.*`. **기존 키의 의미는 바꾸지 않는다**(기준선 재현).

## 5. 지각 범위

- MVP는 통로(폭 0.8 m, 길이 3.5 m) 안 복셀만 군집했다. 좁은 복도에서 벽·천장이 모든 물체를 한 군집으로 묶는 문제(MVP v0.2.4) 때문이다. 이 단계에서는 **분할로 구조물(벽)을 먼저 떼어 낸 뒤** 범위를 넓힌다.
- 관심 영역(후보): 머리 기준 전방 ±`perception.halfAngleDeg`(가설 60°), 반경 `perception.radiusM`(가설 4 m), 바닥 위 `perception.heightM`(2.0 m)까지.
- 통로는 위험도(§8.2)와 STOP 판정에만 쓴다.
- 구조물(벽·문·기둥 열 같은 큰 평면)은 소리를 낼지, 다른 음색으로 낼지, 내지 않을지가 미결정이다(§14). 기본은 **물체와 구분해 기록만** 하고 음원화 여부는 설정.

### 6.1 맵(복셀) 정확도 (v0.2.1)

평가 GUI로 정답 세션을 보며 **점유 복셀이 실제 세계를 정확히 나타내지 못하는 것**을 확인했다(사용자 정성 확인, M11): S02에서 캐리어와 그 뒤 약 2 m의 문·벽이 한 물체로 합쳐지고, 복셀이 물체 둘레로 흩어진다. 군집·추적·음원화는 모두 맵 위에서 동작하므로 **M13에서 군집 비교보다 먼저** 다룬다.

- 비교 대상(후보): 깊이 입력(`depth.source` SMOOTHED vs RAW + `depth.minConfidence`), 복셀 크기, 갱신 규칙(`map.minHits`·`hitGain`·`minScore`·`decayPerObservation`·`freeMarginM`), 바닥 판정(`floor.*`). 모두 설정으로 고를 수 있어 sweep·GUI 재실행으로 바로 비교된다. 새 방법(예: 깊이 잡음 모델, 광선 기반 비움)은 같은 방식으로 교체 대상에 넣는다.
- 지표(후보, M13에서 확정): 정답 상자 안에 든 점유 복셀 비율(정밀도), 정답 상자 앞면 중 점유된 비율(재현율), 정답 상자 밖 통로 안 점유 복셀 수(헛 복셀). 구조물은 정답 v2 `kind: structure`로 표시해 따로 센다.
- 자동 합격 기준은 계속 합성 장면이다. 합성 장면에 깊이 잡음(MVP SC-11 계열)을 넣어 지표가 기대 방향으로 움직이는지 먼저 확인한다.

M13 1차 시도(PR #33~#36, 닫힘)에서 막(ARCore 일반 깊이가 물체 가장자리와 뒤 배경 사이를 평활·보간해 만드는 가짜 점)을 지도·복셀 단계 또는 한 프레임의 단순한 기준(그림자 필터, 빈 공간 여유, 시간 일관성, 다시점, 원시 깊이 신뢰도, RGB 색)으로 지우려던 여섯 방법은 모두 실측에서 실패했다. 선행 연구는 가장자리 결함과 물체 경계를 **지도에 넣기 전 깊이 영상에서** 처리한다(flying pixel 식별, Voxblox++의 프레임 분할). 그래서 개선의 순서를 다음과 같이 정한다. 모든 단계는 설정으로 켜고 끄며 **기본값은 MVP 동작을 재현**한다(§3-2). 설정 키 이름은 구현 때 확정한다.

- **M13.1a 구현(v0.3.7)**: `core/frontend/EdgeDetector`. 가로·세로·두 대각선 주사선을 앞에서부터 선형 조각으로 나눈다(맞춤 오차 ≤ `edgeFitTolRatio` × 깊이). 픽셀당 깊이 변화가 깊이의 `edgeSteepRatio`를 넘는 조각과 한 픽셀 조각을 경사 조각, 나머지(두 픽셀 이상)를 표면으로 본다. 길이가 아니라 **기울기로 가르는 이유**: 막 앞의 뒤 배경 끌림처럼 완만하게 휜 표면은 짧은 조각으로 잘리기 쉬워, 길이로 가르면 경사 묶음이 한도를 넘어 실제 막을 놓친다(실측 E01h 막 경사 9~25%/픽셀, 끌림 1~3%/픽셀). 이웃한 두 표면 사이 경사 조각들(합 ≤ `edgeMaxRampPx`)에서 두 표면이 맞닿는 끝 깊이 차가 가까운 쪽의 `edgeMinStepRatio`를 넘으면, 두 표면 직선 어느 쪽에서도 벗어난 경사 픽셀을 경계로 표시한다. 대각선은 평활이 가로·세로로 함께 섞이는 물체 모서리용이다(없으면 SC-21에 1칸 남음). **수평면 예외**: 경사 픽셀들의 높이(깊이 촬영 자세의 중력 방향) 변화가 깊이 변화의 `levelMaxSlope` 배 + `levelTolM` 이하이고 카메라보다 `levelMinBelowCameraM` 이상 낮으면 다가가며 비스듬히 보이는 윗면으로 보고 남긴다(13번 계획서 위험 ③). 막은 내려다보는 광선을 따라 늘어선 점이라 높이 변화가 깊이 변화 × tan(내려다보는 각)이므로, 높이 차의 절대값으로 판정하면 얕은 각의 짧은 막(높이 차 5 cm 안)을 윗면으로 오인한다. 경계 픽셀은 `LocalMap`에서 무효(0)로 바꿔 지도·바닥 추정·빈 공간 감쇠 모두에서 뺀다(신뢰도 거르기와 같은 자리). viewer는 앞단을 켠 설정이면 영상의 깊이 겹침에 경계 픽셀을 자홍으로 그린다.

- **과적합 방지 평가 규칙(v0.3.8, 사용자 지적 2026-10-08)**: 실제 녹화가 한 장소·한 기기·한 물체(캐리어)뿐이고 같은 세션으로 설계와 평가를 해 왔다. 이후 단계는 ① 상수는 문헌 기본값이나 물리 모형에서 정하고, 실제 세션으로 맞추지 않는다. 조정이 필요하면 장면과 무관한 합성 SC로만 정한다. ② 실제 세션은 **조정용**(E01h 151747·151835, E02 152354·152720, S02 130646·130815·130834)과 **확인용**(E03, E04, S03, S07, S01)으로 나눠 따로 보고하고, 확인용에서 나빠지면 채택하지 않는다. ③ 기본값을 켜기 전에 **다른 공간 녹화**(넓은 복도·방·야외, 다른 바닥재, 의자·기둥·사람)로 확인한다. ④ 사람·자세에 묶인 값(예: `floor.minBelowCameraM` 0.8 m)은 시작 때 카메라 높이의 비율 같은 상대값으로 바꾸는 것을 검토한다.
- **M13.2 구현과 결과(v0.3.8): 채택하지 않음.** 확인용 세션에서 STOP 누락(S07·S01 각 1)과 오경보 증가(S01 0.43 → 0.97), 벽·문 두께는 그대로(`docs/M13_REPORT.md` §3). 벽 두께의 주원인은 매 프레임 평활 깊이의 오차다. 구현: `map.mode` LOG_ODDS(`VoxelMap`). 칸마다 로그 오즈, 점이 들면 + `logHit` × 가중치, 시야 안에서 칸을 지나 더 멀리 보이면 + `logMiss` × 가중치(여유 = max(복셀, `freeMarginRatio` × 칸 깊이)), [`logMin`, `logMax`]로 묶고 하한에 닿으면 지운다. 가중치 = min(1, (`weightRefM` / 거리)²). 시야 밖·무효·가려진 칸은 그대로(§2.2-6), 지나감·오래 안 보임·반경 밖 삭제와 추적 복귀 축소(로그 오즈를 0 쪽으로)는 기준선과 같은 자리.

  - **벽을 먼저**: 카메라 높이 둘레 띠(`wallBandBelowM`~`wallBandAboveM`)의 점을 위에서 본 직선으로 순차 RANSAC(최대 `wallMaxPlanes`), 점 ≥ `wallMinPoints`·길이 ≥ `wallMinLengthM`·높이 범위 ≥ `wallMinHeightM`이면 수직 평면. 세로 파지 가로 시야(약 ±20°) 때문에 1 m 앞의 끝 벽은 0.7 m만 보여 길이 기준에 못 미친다. 복도의 양쪽 벽 점은 두 평행선이라 수평 퍼짐 검사를 통과하므로 벽 점을 바닥 후보에서 뺀다(S02 실측).

## 8. 음원 선택과 음원화

### 8.1 음원 선택

- `sonify.maxSources`: 0이면 무제한(실험 기본), 양수면 상한. 정성 평가로 적정 개수를 정한다.
- 후보 물체: 확인된 물체 중 관심 영역 안. 구조물은 `sonify.includeStructures`로 선택.

### 8.2 우선순위 (위험도)

- 진행 방향 통로 안 + 가까움 → 높음, 통로 밖·멀다 → 낮음. 머리 높이(`HEAD`)는 같은 거리에서 한 단계 높게.
- 우선순위는 음량·펄스 주기·음색에 반영한다(가설, §9.3으로 검증).

### 8.3 안전 규칙 (변형 불가)

1. STOP 대상(통로 안 `policy.stopM` 이내)이 있으면 그 음원이 가장 크게 들리고, 다른 음원은 `sonify.duckDb`만큼 낮춘다.
2. 정보 나이가 허용치를 넘은 물체는 소리를 내지 않는다(MVP §2.2-4). 모든 물체가 만료면 확인 불가 상태로 간다.
3. 무음을 "없음"으로 안내하지 않는다.

## 9. 평가

### 9.1 정답 형식 v2 (`annotations/obstacles.json`)

v1과 호환한다(v1 파일은 그대로 읽힌다). 추가 항목:

```json
{
  "version": 2,
  "scene": "R02",
  "distanceFrom": "camera",
  "obstacles": [
    { "name": "box_left", "type": "FLOOR", "kind": "object", "min": [-0.9, 0, 2.2], "max": [-0.5, 0.4, 2.5] },
    { "name": "wall_right", "type": "FLOOR", "kind": "structure", "min": [0.7, 0, 0], "max": [0.75, 2.4, 6] }
  ]
}
```

- `scene`: 장면 ID(M10에서 폴더 이름의 장면 ID가 틀린 녹화가 생겨 도입).
- `distanceFrom`: `"camera"`면 앞쪽 거리를 시작 시 카메라에서 잰 값으로 보고 분석 도구가 `head.offsetFromCameraM`만큼 보정한다(M10에서 사람이 매번 0.39 m를 더하던 일을 없앰). 없으면 `"start"`(시작 표시, v1과 같음).
- `kind`: `object` | `structure`. 구조물은 탐지율 분모에서 빼고 "구조물을 물체로 안내한 비율"을 따로 잰다.

### 9.2 정량 지표 (기준값은 가설)

| 지표 | 계산 | 기준(가설) |
|---|---|---|
| 물체 탐지율 | 관심 영역 안에 1 s 이상 있었던 정답 물체 중 음원이 난 비율 | ≥ 90% (높이 ≥ 30 cm) |
| 첫 탐지 거리 | 정답 물체에 처음 음원이 난 순간의 실제 거리 | 출발 거리의 90% 이상 |
| 방위 오차 | 음원 방위 − 정답 최근접점 방위, 물체별 p95 | ≤ 6° (MVP 기준 유지) |
| 거리 오차 | (추정 − 정답)/정답, 물체별 p95 | 과대추정 ≤ 10% |
| 오탐 음원 비율 | 어떤 정답과도 맞지 않는 음원-시간 비율 | ≤ 10% |
| 합쳐짐·갈라짐 | 정답 1개에 음원 2개 이상 / 음원 1개가 정답 2개에 걸침 | 측정 후 설정 |
| id 전환 | 같은 정답 물체에 붙은 음원 id가 바뀐 횟수(세션당) | ≤ 1 |
| STOP 누락 | MVP와 같음 | **0 (필수)** |
| 단계별 처리 시간 | 분할·군집·추적·음원화, PC ms/깊이 프레임 | 기록만 |

- 지표는 `tools/analysis/metrics.py`를 확장하고, 비교는 `sweep.py`·`report.py --group`(M10)을 그대로 쓴다.
- **안내 성적표(M12.2, v0.3.15)**: 물체 하나 장면의 "잘 된다"를 지도 모양이 아니라 사용자가 듣는 안내 값으로 판정한다. 항목·목표·여유·세션 구분은 `tools/analysis/scorecard.json`, 판정은 `scorecard.py`(세션 단위). 위 표에 더해:

  | 항목 | 계산 | 기준(가설) |
  |---|---|---|
  | 방위 오차(판정용) | 위 방위 오차 중 정답 최근접점이 머리 **앞**(along > 0)인 경고만(`directionErrorAheadDeg`). 옆·뒤(통로 뒤 여유 `behindM` 안, 카메라가 못 보는 곳)는 비율만(`besideFraction`) | ≤ 6° |
  | 첫 경고 거리 | 처음 WARN을 낸 순간의 정답 거리 ÷ min(출발 거리, `warnMaxM`). 출발 거리 = 정상 상태에서 처음 정답 통로 안에 든 순간의 거리. 정답이 경고 구간에 1 s 이상 있었던 장애물만 | ≥ 0.9 |
  | 첫 STOP 거리 | 처음 STOP을 낸 순간의 정답 거리 ÷ `stopM`. 정지 구간에 1 s 이상 있었던 장애물만 | ≥ 0.9 |
  | 경고 놓침 | 정상 상태에서 정답 구간이 WARN·STOP인 블록 중 추정이 WARN·STOP이 아닌 비율 | ≤ 10% |
  | 통로 밖 경고 | 경고 중 짝지은 정답이 그 블록에서 정답 통로 밖인 비율(옆 벽 등) | ≤ 10% |
  | 부호 있는 거리 오차 | 추정 − 정답(m), 정답 거리 [0, `stopM`)·[`stopM`, 1.5)·[1.5, ∞) 구간별 p05·p50·p95 | 진단(판정 없음) |

  판정은 합격·경계·불합격·해당 없음. 경계 = 값이 목표 ± 여유 안(방위: 그 세션의 정렬 각도 불확실성, 거리: 줄자 0.03 m, 비율·개수 항목은 여유 없음). 합쳐짐·폭은 안내 값을 거쳐서만 사용자에게 닿으므로 진단으로 둔다(사용자 결정 2026-10-10). 첫 경고는 시간이 아니라 거리로 판정한다(보행 속도 0.38~0.70 m/s라 초 단위 지연은 과장된다).
- **정답 진행 방향(M12.2, v0.3.15)**: 정답 통로 방향은 보행선 ±z 중 최근 이동 쪽이다. 블록마다 머리 z가 `heading.windowS` 동안 `heading.minTravelM` 이상 움직였으면 그 부호, 아니면 직전 부호(처음 +z, 과거만). 정답 장면이 곧은 복도라 ±z로만 두며, 앱 진행 방향의 흔들림은 방위 오차에 남는다. 이전에는 늘 +z라 왕복 세션(E03·E04)의 돌아오는 구간 방위 오차가 117~152°로 나왔다.
- **경고 놓침 사유(M12.3, v0.3.16)**: `missedWarnReasons` = 경고 놓침 시간(s)을 사유별로. core 로그를 늘리지 않고 기존 실행 로그로 가른다(블록이 쓴 `snapshotTNs`로 느린 경로 로그를 찾아 위에서부터 처음 맞는 것): `silent`(음원은 있으나 SILENT) → `noSnapshot` → `outOfBand`(그 시각 장애물은 있으나 명령 없음: `silentMaxM` 밖·머리 뒤) → `noFloor`(`slow_path.csv` floorY 없음 → 빈 스냅샷) → `noCluster`(`cluster_debug.csv`에 군집 없음) → `allFiltered`(오경보 거르개) → `unconfirmed`(추적 확인 대기). 정책은 정보 나이 초과·머리 뒤·`silentMaxM` 밖에서만 음원을 버리고 구조물 거르기는 없으므로 이 목록으로 모든 놓침이 갈린다.
- **정답 대입 재생(M12.3, v0.3.16, 평가 전용)**: 처리 단계 출력을 정답으로 바꿔 다시 재생하고, 변형 사이 성적표 차이를 그 단계의 몫으로 본다(`./gradlew :core:replay … -Psubstitute=depth,map,heading -PalignFrom=<align.json> [-PdepthNoisePerM=]`, `core/truth/Substitution.kt`). 앱 설정 키가 아니라 재생 인자다.
  - `depth`(D): 깊이 장마다 기록된 자세·내부 파라미터로 정답 상자와 바닥(정답 y = 0)을 그린 깊이(합성 렌더러와 같은 계산, 8 m 밖 무효). `depthNoisePerM` > 0이면 화소마다 정규 잡음 σ = 계수 × 거리(Dn, 시드 = 깊이 시각).
  - `map`(O): 바닥 추정·복셀 점유 대신 정답 상자를 복셀 크기 격자 점으로 채운 고정 지도와 정렬의 바닥. 통로·가장자리 구조물 규칙·군집·대표점·추적은 그대로.
  - `alignFrom`만 주면 대입 없이 그 정렬만 기록한다(M18, v0.3.17: 바닥 규칙을 바꾼 변형이 재생의 바닥 추정에 기댄 정렬을 바꾸지 않게).
- **진단 지표(M18, v0.3.17)**: `headingErrorDeg` = 앱 진행 방향 − 정답 보행 방향(정렬의 ±z)의 p50·p95, 최근 1 s 보행선 방향 속도 > 0.25 m/s인 블록만. `floorErrorM` = 느린 경로 바닥 추정 − 정렬 바닥의 p05·p95·최대와 첫 추정 뒤 바닥 없음 비율. 정답 진행 부호(`walk_sign`)의 창은 재생 덮어쓰기와 무관하게 기본 설정 값을 쓴다(진행 방향 창을 바꾼 변형에서 정답이 같이 바뀌지 않게).
  - `heading`(H): 앱 진행 방향 h를 보행선 축 z<sub>W</sub>에 맞춰 sign(h·z<sub>W</sub>)·z<sub>W</sub>(정답 진행 방향과 같은 규칙).
  - 정렬은 기준 재생의 `align.json`을 모든 대입 변형이 같이 쓴다(`replay_info.json`의 `substitution.alignFrom`을 `align.py`가 읽음). 정렬이 재생의 바닥 추정 중앙값에 기대므로 변형마다 맞추면 정답이 달라진다.
  - 변형: B(없음) · D · Dn(0.03) · O · H · DH · OH (`tools/analysis/sweeps/m12_3_substitution.json`). 대입 결과로 상수를 정하지 않는다(과적합 규칙).
- 자동 테스트의 합격 기준은 합성 장면이다(MVP §14-6). 여러 물체 합성 장면(§12)을 추가한다.

### 10.1 구성

- 새 Gradle 모듈 `:viewer` (Kotlin/JVM). **Swing·`javax.sound.sampled`만 사용(JDK 내장, 새 의존성 없음)**. `:core`에만 의존하고 `:app`에는 의존하지 않는다.

- **정지 녹화의 정렬(v0.3.3, MVP §10.3 보완):** 카메라가 `align.minTravelM`(0.5 m)보다 적게 움직인 세션은 궤적 방향이 손 떨림 잡음이라(E01h 세 세션에서 궤적 방향 1.6°·48.9°·152°, 카메라 시선 −0.9°·−1.2°·−0.8°) 처음 `align.headingWindowS`(3 s) 동안 카메라 시선의 수평 성분 평균을 +z로 쓴다(`Alignment.byHeading`, 불확실성 = 그 창에서 시선의 흔들림 각). 걷는 세션은 기존대로 궤적에 맞춘다. 대가: 손 파지 각도 오차(MVP §10.3이 피하려던 것)가 정지 녹화에는 들어간다.

### 10.3 오디오

- 재실행 때 `core` 바이노럴 렌더러로 세션 전체 스테레오 PCM(48 kHz)을 미리 만든다. 화면 재생 위치 = 세션 시각.
- 재생은 1배속과 임의 위치 이동만 지원한다(느린 재생은 음높이·시간 단서를 바꾸므로 제외).
- 렌더 결과는 WAV로 내보낼 수 있다(팀 공유·시연용).

### 10.4 성능 목표

- 15초 세션 재실행(재생 + 오디오 렌더) ≤ 5 s (PC). 넘으면 진행 표시와 함께 백그라운드로.
- **M11 실측**(개발 PC): 9.4 s 세션(S02) 처음 3.0 s, 15.4 s 세션(빈 복도 190833) 처음 6.4 s · 이후 4.8~5.0 s. 소리·복셀 복사 없이 재생만 4.4 s라 **병목은 core 파이프라인(주로 군집 단계, 이 세션 깊이 프레임당 약 7.8 ms)**이다. 측정 근거 없는 최적화는 하지 않으므로(MVP §14-7) 군집 방법을 바꾸는 M13에서 다시 잰다.
- Swing 이벤트 스레드에서 `core`를 돌리지 않는다.

## 11. 평가용 녹화 세트 (M12)

M10 공간(폭 약 1 m, 길이 4~5 m)에서 찍을 수 있게 구성한다. 모든 장면 공통:
- **장애물에서 3 m 이상 떨어져 출발**(첫 탐지 거리·경고 시점을 잴 수 있게, M10 교훈)
- 녹화 화면에서 **장면 ID 선택 확인**, 앞쪽 거리는 카메라 또는 시작 표시 중 하나로 재고 `distanceFrom`에 적는다
- 좌우 위치는 보행선 기준 줄자로(M10 S03의 0.25 m 불일치 교훈)

### 11.1 M12.0 오차 분해 녹화 (v0.3.1, 사용자 결정 2026-10-06)

**근거.** 2차 산업체 멘토링 이슈 A(`references/14_2차_산업체멘토링_정리.pdf`): 복셀 맵이 현실과 다른 오차가 어디서 나는지(누적 오차인지 등) 먼저 테스트하라는 의견. 지금 녹화(M10)는 한 번에 1.5~1.7 m를 걷는 단방향이라 자세(VIO) 누적 오차를 잴 수 없다. M13의 순서(막 대책 M13.1이 먼저인지, 지도 규칙 M13.2가 먼저인지)는 오차원별 크기에 달려 있으므로 **M13.0 시작 전에 이 녹화와 분석을 끝낸다**. 한 번에 한 가지 오차원만 더 켜면서 같은 지표를 재고, 단계 사이의 증가분을 그 단계가 더한 오차로 본다.

## 15. 작업 규칙 (MVP §14에 더해)

1. `:viewer`는 Swing 이벤트 스레드에서 UI만 다루고, `core` 실행과 오디오 렌더는 백그라운드 스레드에서 한다.
2. `:viewer`에 알고리즘을 두지 않는다. 표시용 변환(좌표 → 화면)만 둔다.
3. 새 방법은 먼저 기준선과 같은 세션·지표로 비교하고, 기본값 변경은 비교표와 함께 제안한다(사용자 결정).
4. 정답 v2를 쓰는 도구는 v1 파일도 읽는다.



## 15. 접근 연속음 후보 구현 (2026-10-03)

- `sonify.mode`: `PULSE`는 기존 기준선, `RISK_CONTINUOUS`는 사용자 청취로 선택한 후보.
- 앱은 `AppConfig`에서 `risk-continuous.override.json`을 병합해 후보를 활성화한다. 기본 JSON만 읽는 기존 PC 테스트는 기준선을 유지한다. viewer도 앱과 같은 순서(default.json → 이 파일 → viewer 변형)로 쌓는다(v0.3.14: 이전에는 변형을 불러오면 이 파일이 빠져 PULSE로 재생됐다).
- RiskSoundGenerator는 물체 ID별 최근 `sonify.historyS` 상대 거리 관측으로 closingMps/TTC를 계산한다. 미래 관측은 쓰지 않는다.
- 신규 물체/거리 구간 변화 시 `onceS` 동안 안내하고, 접근 중에는 연속음을 유지한다. 통로 안 STOP은 정적이어도 지속하고 다른 음원은 `duckDb` 감쇠한다.
- 거리 음높이는 nearM/farM 사이의 지수 매핑. TTC와 근접도는 진폭과 배음 비율에 반영한다. HEAD_TONE은 headPitchRatio로 음높이를 구분한다.
- 만료된 명령 및 UNKNOWN/PAUSED는 음원/합성곱 이력을 즉시 버린다. 신선한 동일 ID 재등장은 신규 안내로 처리한다.
- policy.prioritizeStop이 켜지면 통로 안 STOP 후보를 먼저 선택한다. 기존 공간 관심영역/군집 확장은 이 변경에 포함하지 않는다.
- HRTF, 비공간 알림음, 주 음량, 리미터, 최신 값 교체 방식은 기존 구현을 재사용한다.
- 음원별 모노/이력 배열은 생성 시 할당한다. 실기기 처리 시간·발열·끊김·사용자 보행 성능은 이후 측정한다.
- 자동 검사는 RiskSoundGeneratorTest, RiskPolicyTest, ConfigLoaderTest, BinauralTest.riskContinuousWavs로 한다.
- 무음은 장애물 없음/안전으로 해석하지 않는다. 이 변경만으로 M15 전체 완료를 선언하지 않는다.

### 15.2 거리·방향·높이 단서 분리 (2026-10-07 사용자 요청)

- `sonify.mapping=DISTANCE_HEIGHT`: 수평 거리 → 선형 진폭, 머리 기준 대표점 높이 차 → 지수 주파수, 방위각 → 기존 수평 HRTF.
- 높이 전달: `AudioCmd.heightDeltaM = obstacle.repPointW.y - head.positionW.y`. 기본 0m는 기존 호출 호환용이며 Policy 경로는 반드시 실제 값을 전달한다.
- 높이 기본 매핑 범위 `heightLowM=-1`, `heightHighM=1`; `minHz=250`, `maxHz=1000`. -1m 이하=250Hz, 0m=500Hz, +1m 이상=1000Hz.
- `nearM/farM` 정규화 거리로 minGain~maxGain을 보간하고 prototypeGain과 duckGain을 적용한다. 위험도에 따른 gain/배음 변화와 HEAD 별도 주파수 배율은 이 매핑에서 사용하지 않는다.
- closingMps/TTC/risk 계산과 관측은 계속한다. 기존 once/approaching/STOP 활성 규칙, SILENT/만료/UNKNOWN 음원 제거, STOP duck은 유지한다.
- 기존 `LEGACY_RISK`는 A/B 비교용으로 보존한다. 기본 JSON의 PULSE/LEGACY_RISK 기준선은 유지하고 앱 override와 PC GUI/내보내기 시작 설정은 DISTANCE_HEIGHT로 선택한다.
- CSV 끝에 heightDeltaM/mapping 열 추가. 기존 열 순서는 보존. pitch/gain은 블록 끝 값, 같은 WAV의 frameStart를 시간 기준으로 삼는다.
- 이 높이는 물체 전체 크기나 최상단 높이가 아니라 선택된 대표점의 위치다. 머리 Y는 기존 카메라 오프셋 기반 추정이다. 새로운 고도 HRTF나 실기기 검증은 포함하지 않는다.
