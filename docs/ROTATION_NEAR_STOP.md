# 회전 중 첫 STOP 지연 개선 실험

2026-11-07. `fix/rotation-near-stop`, 기준 `fix/chest-mount-calibration`의 `46ec77cb5c1c4cde39eccc93c5cb1b5d8d182ddf` (PR #98). main 직접 변경 없음.

## 변경

현재 가슴 방향 보정은 회전 후 안내를 안정시키지만, 복셀이 6장의 관측을 누적하고 추적 확인을 받기 전의 첫 경고 지연은 남는다. 새 `NearStopDetector`는 현재 깊이의 필터링된 바닥 위 점을 사용해 근거리 STOP 후보를 만든다. 지도 점유 문턱이나 기존 Tracker 확인 횟수를 낮추지 않는다. 기본 `policy.nearStop=null`은 OFF다.

- LocalMap의 기존 현재 장 장애물 점 수집을 재사용한다. 신뢰도·깊이 앞단·바닥 처리를 거친 점이다. 별도 원시 영상 경로를 만들지 않는다.
- 바닥이 알려지고 mapHealth가 OK인 HITS 지도에서만 실행한다. 바닥 불명/DEGRADED/RESET은 초기 경고 상태를 지운다.
- 현재 몸 정면 통로 안, 앞 거리 0~`policy.stopM` 미만, 설정한 바닥 여유 위에 있는 점을 공간 셀별 한 표로 줄인다. 같은 셀의 화소 1,000개가 공간 지지 1,000표가 되지 않는다.
- 기존 DBSCAN eps/minSamples로 묶고 서로 다른 셀 수·높이 폭·좌우 폭을 확인한다. 폭이 매우 좁거나 낮은 물체는 빠른 경로가 놓칠 수 있으며 기존 지도 경로가 계속 담당한다.
- 연속된 서로 다른 깊이 장에서 기존 matchRadius 안의 후보를 확인한다. 동일 시각 깊이 반복·과거 시각을 확인 횟수로 세지 않는다. 관측 공백이나 후보 소실 시 누적을 끊고, 현재 보이지 않는 후보를 출력하지 않는다.
- 정식 근거리 track과 상자가 겹치면 임시 후보를 제외한다. 임시 후보는 음수 ID/`earlyStop=true`, 정식 track은 기존 ID다. 임시 후보는 기존 지도·Tracker의 상태나 ID를 수정하지 않는다.
- Policy는 현재 머리 자세에서 앞/좌우 통로와 정보 나이를 다시 확인하고 STOP만 허용한다. WARN으로 남거나 오래된 후보가 새 스냅샷 시각으로 갱신되는 것을 허용하지 않는다.
- 음원 수가 부족하면 기존 확인된 STOP을 임시 STOP보다 먼저 선택한다. UNKNOWN·PAUSED·전역 정보 만료 등 기존 상태/음원 규칙은 유지한다.

## 설정

모든 새 문턱은 `app/src/main/assets/config/near-stop.experimental.override.json`에 있다. 아래 값은 합성 비교용 휴리스틱이며 실기 유효 범위로 검증되지 않았다.

| 값 | 실험 값 |
|---|---:|
| minVoxels | 12셀 |
| minHeightSpanM | 0.15m |
| minLateralSpanM | 0.08m |
| minAboveFloorM | 0.15m |
| confirmFrames | 2개의 서로 다른 깊이 장 |
| maxGapMs | 150ms |
| maxAgeMs | 150ms |

공간 셀 크기·군집 eps/minSamples·매칭 거리는 기존 map/cluster/track 설정을 사용한다. ConfigLoader는 paired chestMount, HITS, prioritizeStop을 요구하고, 확인 1장·과도한 정보 나이·비유한 값·통로보다 큰 지지 문턱을 거부한다. 과거 설정에 nearStop 키가 없는 경우도 OFF로 읽는다.

실제 기기의 깊이 처리 간격이 150ms를 넘으면 이번 프로필은 연속 확인을 끊는다. 처리 결과를 받을 때 이미 150ms가 지난 후보도 재생하지 않는다. 따라서 PC 30Hz 결과가 낮은 처리율의 실제 앱에서 그대로 재현된다고 가정하지 않는다. 실제 장 간격·계산 시간·정보 나이를 측정해야 한다.

## 비교 실험

기존 112조건은 그대로 두고 NEAR_CHEST 30조건 및 장애물 없는 대조 44조건을 추가했다. 총 **186조건·558구간 행**이다. 현재 자세/깊이와 기존 FastPath·SlowPath·Policy를 실행하며, 최종 명령을 30Hz로 표본화한다. 실제 Android 스레드·오디오 렌더러를 돌린 실험은 아니다. 결과 전달 시간은 기존 비교와 같은 가상 10ms다.

기존 기본 회전은 ±90·±180도 × 0.5·1초 × 잡음 없음/±1%(seed 7), 방식별 16조건이다. 평가 사건은 정답 상자 **중심**이 몸 기준 전방 1m·좌우 ±0.4m 안에 있는 시각이다. STOP 비율은 이 사건 표본 중 해당 상자에 STOP 명령이 있는 비율이다. 모든 물체 위험이나 일반 탐지 정확도를 뜻하지 않는다. 대상 연결은 대표점과 정답 상자 표면 거리가 복셀 두 칸 이내인 출력이다.

| 구간 | 가슴 방향 보정만 | NearStop 추가 |
|---|---:|---:|
| 회전 중 | 12/72 = 16.7% | 53/72 = 73.6% |
| 회전 직후 1초 | 448/480 = 93.3% | 479/480 = 99.8% |
| 이후 2초 | 976/976 = 100% | 976/976 = 100% |

첫 평가 사건 이후 STOP 표본 지연은 기본 회전 조건에서 약 167~200ms → 0~67ms였다. 0ms는 사건 진입 시각에 이미 STOP 명령이 있다는 뜻이며 센서·계산·소리까지의 물리적 지연 0ms가 아니다.

잡음 없는 +90도/1초는 회전 중 37.5% → 100%, 지연 167 → 0ms였다. 반면 −180도/0.5초는 이번 프로필에서도 회전 중 0%로 남고 첫 경고는 약 67ms 뒤다. 양쪽 회전의 차이는 화소·관측 지지 조건에서도 생기므로 전체 성공으로 판단하지 않는다.

대조는 벽이 약 3m 떨어진 빈 방 회전(방식별 16조건)과 몸 정면에 평행한 측면 벽(반폭 0.45·0.55·0.8m × 두 잡음, 방식별 6조건)이다. 양쪽 방식 모두 준비 1초 이후 2,542표본에서 STOP 0회였다. 단일 장 유령 면·중복 화소·점 잡음·바닥 점 등은 신규 단위 테스트로 확인한다. 지속적인 반사면/다중 장 깊이 오차나 실제 촬영의 오경보율을 검증한 결과는 아니다.

## 남은 한계

- 임시 ID에서 정식 ID로 넘길 때 소스 ID가 바뀐다. 기본 회전에서 대상 STOP ID 수는 1 → 2였다. 이 지표는 스위치 횟수와 같지는 않다. 별도 음향 청취·트래킹 연속성 검증이 필요하다.
- 빠른 −180도 회전 일부는 여전히 첫 경고가 회전 뒤에 나온다. 시야에 들어오지 않은 위험을 알아내지는 못한다.
- 두 장 이상 지속되는 깊이 유령 면은 공간/시간 조건을 통과할 수 있다. 현재 값은 실제 반사·블러·추적 보정·사람 움직임 데이터로 검증되지 않았다.
- 기존 임시/정식 후보 상자 중복 제거는 기하 근사다. 움직이는 물체 TTC·긴 상자 군집과 조합한 품질은 별도 검증 대상이다.
- 하네스 실제 치수나 175cm·75kg 가정의 위 40cm·뒤 15cm 값을 이번 실험에 적용한 것은 아니다. 이전 비교와 같은 합성 치수를 썼다.
- 기존 map freeEvidenceDecay·coreEvidenceMultiplier·전역 minHits/추적 확인 수·바닥 기하 안내는 변경하지 않았다. 기본 OFF다.

## 실행

이 브랜치는 PR #98의 가슴 보정 위에 쌓은 작업이다. PC에서 설정 없이 비교 전체를 실행한다. CSV를 열어 둔 상태로 같은 폴더를 덮어쓰지 말고 새 출력 폴더를 쓴다.

```powershell
git fetch origin
git switch fix/rotation-near-stop
git pull --ff-only origin fix/rotation-near-stop
.\gradlew.bat :core:test :core:chestGuidanceExperiment -Pout=core/build/near-stop-run1
explorer .\core\build\near-stop-run1
```

`cases.csv`는 지표, `trace.csv`는 프레임별 상태·임시 명령 수, `stage_timing.csv`는 PC의 실제 단계 처리시간이다. 정적 참조: [rotation_near_stop_cases.csv](rotation_near_stop_cases.csv). 원래 CSV 열 뒤에 anyStopTicks·hasTarget·roomHalfWidthM·targetStopIds를 추가했으며 예전 공통 열 값으로 OFF 회귀를 비교한다.

기기에서는 **이 코드로 빌드한 앱**과 하네스 보정 설정이 필요하다. 기존 기기 override를 백업하고 근거리 실험 JSON의 policy 객체를 기존 하네스 설정에 깊게 병합한 파일을 별도 이름으로 만든 뒤 검증/적용한다. 근거리 JSON만 기기로 보내면 하네스 치수가 없으므로 거부된다. 기존 파일을 무조건 교체하거나 main 기본값을 켜지 않는다. 기기 설치·실제 치수 적용·청취·회전 촬영은 아직 하지 않았다.

## 검증 기록

- 레포와 같은 Kotlin 2.4.20 CLI로 core production/전체 테스트 컴파일, 기존 선언 버전 JUnit 6.1.3과 Gradle과 같은 설정·HRIR·출력 경로로 core **404/404 통과**(새 합성 테스트 9개 포함). 단일 장 면, 반복 깊이, 역행 시각, 긴 관측 공백, 바닥/측면/원거리/중복 화소/점 잡음, 성숙 track 중복, 정보 만료·현재 ROI, 기존 STOP 우선, 설정 거부를 확인했다.
- 186조건·558구간을 독립 JVM에서 두 번 실행. cases.csv/trace.csv가 각각 바이트 단위로 같았다. cases SHA-256 `bc82ccffd8097b617d0587ad0e4bcdf9002502fc798e152d233fa8abde195fad`, trace SHA-256 `5e692ecd4c9c9866669d121166316f89cd7bdc73c17650787e833cc5bdef75b7`.
- OFF의 기존 112조건 모든 기존 CSV 열이 PR #98 결과와 같았다. 558개 조건/구간 행의 고유성, 대조에서 STOP 0회도 CSV로 교차 확인했다.
- 두 번째 실행은 비결정적인 실제 시계 데이터를 별도 stage_timing.csv에 기록했다. 기본 회전의 같은 방식당 2,296프레임에서 SlowPath 전체 p95는 가슴 보정만 4.643ms / NearStop 포함 4.877ms, 추적+근거리 단계 p95는 0.006 / 0.853ms였다. 다른 회귀 테스트가 동시에 실행된 PC 측정이며 두 p95의 차이를 순수한 추가 비용으로 해석하지 않는다. 기기 처리 시간이나 실제 소리 지연은 측정하지 않았다.
- `git diff --check` 통과. 이 환경의 Gradle은 9.8 배포판 다운로드에서 Network is unreachable로 실패했다. Android 앱 빌드·실기 설치·청취·실제 촬영 오탐 평가는 미완료다. Viewer 전체 시험은 이번 단계에서 다시 실행하지 않았다(PR #98에 기록한 기존 Linux 경로 실패가 남아 있음).
